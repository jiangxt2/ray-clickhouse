# ray-clickhouse 0.1.0

Maturity: Alpha.

## Highlights

- Structured ClickHouse reads returning Ray Datasets through public Ray extension contracts.
- Single-query View and Distributed reads, plus optional validated partition and integer-range splitting for direct MergeTree-family tables.
- Bounded Arrow streaming by row and byte targets.
- Schema-checked synchronous and confirmed asynchronous append writes.
- Explicit restricted `create` and `overwrite` table-management modes.
- Fail-closed authentication, permission, discovery, schema, timeout, transport, write, and table-management errors.

## Compatibility

- Python `>=3.10,<3.14`
- Final Ray releases `>=2.55,<2.59`
- PyArrow `>=19,<20`
- `clickhouse-connect[arrow] >=1.5,<1.6`

## Public contract changes before the first release

- Package-root exports were limited to `read_clickhouse()`, `write_clickhouse()`, `WriteReceipt`, and the error hierarchy.
- Missing Ray write completion receipts now fail closed instead of returning a synthetic zero receipt.
- Empty Dataset writes are confirmed no-ops for append, create, and overwrite modes.
- MaterializedView was removed from the supported read profile pending a separate validated contract.
- Write task retries remain forced to zero through the public facade.

## Verification evidence

- Python 3.10–3.13 and Ray 2.55.0–2.58.0 compatibility matrix.
- ClickHouse 26.8.1.2041 local and required remote integration suites.
- Ray 2.58.0/Python 3.12 three-node local cluster suite.
- Wheel/source-distribution build, Twine, dependency, and isolated-install smoke checks.

## Known limits

- No arbitrary SQL or arbitrary DDL.
- No delete, update, upsert, cross-task transaction, snapshot-isolation, or exactly-once guarantee.
- Multiple read tasks do not share one ClickHouse snapshot.
- Distributed routing remains ClickHouse-owned.
- MaterializedView is not supported.
- An uncertain INSERT response can require application-level reconciliation.
